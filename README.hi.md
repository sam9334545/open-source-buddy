# Open Source Buddy

[English](README.md) | [हिंदी (Hindi)](README.hi.md)

एक AI-असिस्टेड वेब ऐप जो नए योगदानकर्ताओं (beginners) को अपने पहले ओपन सोर्स योगदान को **खोजने, समझने और शुरू करने** में मदद करता है।

- इश्यूज़ (issues) ब्राउज़ और सर्च करें, प्रोग्रामिंग भाषा (language) और विषय (topic) के अनुसार फ़िल्टर करें
- किसी रिपॉजिटरी में समय लगाने से पहले उसकी स्थिति (health) जांचें (अंतिम मर्ज की गई PR, मेंटेनर्स का रिस्पॉन्स समय, CONTRIBUTING.md)
- किसी इश्यू का आसान भाषा में सारांश, संभावित फाइलें और शुरुआती योजना प्राप्त करने के लिए **Explain this issue** पर क्लिक करें
- इश्यूज़ को बाद के लिए सेव करें, लाइट (light) और डार्क (dark) थीम के बीच स्विच करें

यह रिपॉजिटरी **NIT Jamshedpur में Hacktoberfest Hack Day** के लिए स्टार्टर प्रोजेक्ट है। भाग लेने के लिए [CONTRIBUTING.md](CONTRIBUTING.md) देखें।

## सेटअप और चलाने के निर्देश (Setup instructions / Run it)

इसके लिए आपको **Node.js 20 या नए संस्करण** की आवश्यकता होगी (यह Windows, macOS और Linux पर काम करता है)। किसी डेटाबेस या API keys की आवश्यकता नहीं है।

```bash
git clone <your-fork-url>
cd open-source-buddy
npm install
npm run dev
```

इसके बाद अपने ब्राउज़र में http://localhost:5173 खोलें। `npm run dev` कमांड Express API (port 3001) और Vite client (port 5173) दोनों को एक साथ शुरू करती है।

## मॉक मोड बनाम लाइव मोड (Mock mode vs live mode)

| | मॉक / Mock (डिफ़ॉल्ट) | लाइव / Live |
|---|---|---|
| GitHub डेटा | `server/github/mockData/` में लोकल सैंपल JSON | वास्तविक GitHub REST API |
| इंटरनेट की आवश्यकता | नहीं | हाँ |
| UI संकेत | पीला **Sample data** बैनर | कोई बैनर नहीं |

मोड बदलने के लिए, `.env.example` को `.env` में कॉपी करें और उसमें बदलाव करें:

```bash
cp .env.example .env      # Windows पर: copy .env.example .env
```

- `GITHUB_MODE=live` वास्तविक GitHub API का उपयोग करता है। यह बिना किसी टोकन के भी काम करता है (प्रति घंटे 60 रिक्वेस्ट्स / 60 requests/hour)। उच्च सीमा के लिए `GITHUB_TOKEN` जोड़ें।
- `AI_PROVIDER=mock` एकमात्र लागू (implemented) AI प्रोवाइडर है। यह इश्यू के शीर्षक, लेबल्स और विवरण (body) के आधार पर स्पष्टीकरण तैयार करता है।

Keys और tokens केवल सर्वर की `.env` फ़ाइल में सुरक्षित रहते हैं। इन्हें कभी भी ब्राउज़र में नहीं भेजा जाता है।

## API

| Method | Path | Description (विवरण) |
|---|---|---|
| GET | `/api/issues` | इश्यूज़ की सूची प्राप्त करें। क्वेरी पैरामीटर्स: `q`, `language`, `topic`, `sort`, `page` |
| GET | `/api/repos/:owner/:name/health` | रिपॉजिटरी हेल्थ मेट्रिक्स और स्कोर |
| POST | `/api/explain` | Body `{ "issue": {...} }`, AI स्पष्टीकरण लौटाता है |
| GET / POST / DELETE | `/api/saved` | सेव किए गए इश्यूज़ की सूची देखें, नया जोड़ें (`POST`) या हटाएं (`DELETE /api/saved/:id`) |

## योगदान मार्गदर्शन (Contribution guidance)

इस प्रोजेक्ट में योगदान देने के लिए नीचे दिए गए बुनियादी चरणों का पालन करें:

1. **Fork करें**: GitHub पर सबसे ऊपर दाईं ओर स्थित Fork बटन पर क्लिक करके रिपॉजिटरी को अपने खाते में फोर्क करें।
2. **Clone करें और रन करें**: अपने फोर्क को क्लोन करें और ऊपर दिए गए सेटअप निर्देशों के अनुसार एप्लिकेशन चलाएं।
3. **एक इश्यू चुनें**: Issues टैब से कोई एक इश्यू चुनें। इसे पहले से क्लेम करने की आवश्यकता नहीं है; कई टीमें एक ही इश्यू पर काम कर सकती हैं।
4. **नया ब्रांच बनाएं**:
   ```bash
   git checkout -b fix/short-description
   ```
5. **केंद्रित बदलाव करें**: एक छोटा और केंद्रित समाधान तैयार करें जो केवल संबंधित समस्या को ठीक करे।
6. **लोकल टेस्ट करें**: `npm run dev` चलाकर ब्राउज़र में जांचें कि आपका बदलाव सही ढंग से काम कर रहा है।
7. **कमिट और पुश करें**: अपने बदलावों को कमिट करें और अपने फोर्क में पुश करें।
8. **Pull Request (PR) खोलें**: इस रिपॉजिटरी पर एक PR बनाएं और उसके विवरण में `Closes #N` लिखें (जहाँ `N` इश्यू नंबर है)।

महत्वपूर्ण नियम:
- एक PR में केवल एक ही इश्यू पर काम करें। अलग-अलग बदलावों को एक साथ न मिलाएं।
- केवल संबंधित फाइलों में ही बदलाव करें।
- कभी भी `.env`, `node_modules` या सीक्रेट्स कमिट न करें।
- विस्तृत नियमों और स्कोरिंग प्रणाली के लिए [CONTRIBUTING.md](CONTRIBUTING.md) देखें।
